# Feature Specification: 在线编辑 book 内容（仅仓库所有者可见）

**Feature Branch**: `003-online-book-editor`

**Created**: 2026-11-07

**Status**: Draft

**Input**: User description: "1、实现可网页在线编辑book内容的功能 2、只能github所有者能显示这个功能 & 编辑"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 访客看不到任何编辑入口 (Priority: P1)

任何非仓库所有者的访问者（包括未登录访客）浏览站点阅读器时，界面上不出现
任何编辑相关的入口、按钮、菜单或提示。编辑能力对访客完全不可见、不可猜
（即使直接访问编辑相关的 URL 或在控制台执行脚本，也无法保存任何修改）。

**Why this priority**: 站点是公开的个人博客，"编辑功能只属于所有者"是本特性的
第一目标；若泄露给访客，等于向公网开放了内容篡改面，安全与体验双输。

**Independent Test**: 未登录状态打开首页与任一章节，检查页面不出现编辑入口；
尝试直接拼编辑 URL，得到与普通阅读一致的体验（不渲染编辑器）。

**Acceptance Scenarios**:

1. **Given** 访客（未登录）打开首页书架或任一章节，**When** 页面加载完成，**Then**
   页面上不存在任何"编辑""保存""新建章节"等入口或提示。
2. **Given** 访客直接访问编辑视图的地址（手工拼 hash/URL），**When** 页面渲染，**Then**
   不显示编辑器，仍展示正常的阅读界面（或明确的拒绝提示）。
3. **Given** 访客在浏览器控制台尝试触发保存动作，**When** 保存请求发出，**Then**
   保存失败且 `book/` 内容不发生任何变化。

---

### User Story 2 - 所有者登录后可见并进入编辑 (Priority: P1)

站点所有者（本仓库的 GitHub 所有者账号）在浏览器中完成一次身份确认后，
阅读器界面出现编辑入口；点击即可在当前章节进入编辑状态，以纯文本方式编辑
Markdown 原文，并支持实时预览渲染效果。

**Why this priority**: 没有这一步，"在线编辑"无从谈起；它是功能的主干路径。

**Independent Test**: 所有者在浏览器完成登录确认 → 出现编辑入口 → 点击进入
编辑态 → 修改正文 → 预览实时更新。

**Acceptance Scenarios**:

1. **Given** 所有者尚未在本浏览器确认身份，**When** 打开阅读器，**Then** 页面
   提供一个不显眼的登录/确认入口（默认不干扰阅读）。
2. **Given** 所有者完成身份确认且被系统识别为仓库所有者，**When** 打开任一章节，
   **Then** 出现"编辑"入口；点击后正文变为可编辑的 Markdown 文本域，且预览
   区实时同步渲染。
3. **Given** 一个已登录但不是仓库所有者的 GitHub 账号，**When** 打开阅读器，**Then**
   看不到编辑入口（身份校验不通过时等同访客）。

---

### User Story 3 - 编辑保存为仓库提交并自动上线 (Priority: P1)

所有者在编辑态保存修改时，系统将修改后的 Markdown 内容提交到站点仓库的
对应文件，随后站点自动重新部署，稍后刷新页面即可看到新内容。保存前系统
基于最新远端内容校验，避免覆盖他人/其他端的并发修改。

**Why this priority**: "编辑"只有真正落盘并上线才有价值；没有保存的编辑器
只是个记事本。

**Independent Test**: 所有者修改某章节并保存 → 仓库中出现一次新的内容提交 →
数分钟后线上站点该章节内容与编辑结果一致。

**Acceptance Scenarios**:

1. **Given** 所有者在编辑态修改了章节正文，**When** 点击保存，**Then** 保存成功，
   页面提示成功并回到阅读态，正文显示新内容。
2. **Given** 保存成功，**When** 站点完成自动部署后刷新该章节，**Then** 看到的
   是编辑后的内容。
3. **Given** 编辑基于的远端内容在保存时已被更新（并发修改），**When** 点击保存，
   **Then** 保存失败并给出明确提示，编辑内容保留在本地编辑区，可重新拉取
   最新内容后合并重试，MUST NOT 静默覆盖。
4. **Given** 保存过程中网络失败或凭据失效，**When** 保存失败，**Then** 编辑内容
   不丢失，并展示可读的失败原因与重试入口。

---

### User Story 4 - 编辑目录与未保存保护 (Priority: P2)

所有者除编辑章节正文外，还可以编辑各书的目录文件（SUMMARY）：增删章节
链接、调整顺序，使新书/新章节也能完全在网页上维护。编辑未保存时切换
章节/书籍或离开页面，系统给出明确的放弃确认，防止误丢内容。

**Why this priority**: 完善编辑体验，让内容维护不依赖命令行；未保存保护是
内容零丢失原则在编辑场景的延伸。

**Independent Test**: 所有者编辑 SUMMARY 增加一行章节链接并保存 → 目录与
线上同步生效；在编辑态未保存时切换章节 → 出现确认提示。

**Acceptance Scenarios**:

1. **Given** 所有者进入某书的目录编辑态，**When** 增加一行指向已有章节的链接
   并保存，**Then** 该书目录中出现新章节且可点击阅读。
2. **Given** 编辑区存在未保存修改，**When** 所有者切换章节、切换书籍或关闭页面，
   **Then** 系统弹出确认提示，选择放弃才离开，编辑内容在确认前不丢失。

---

### Edge Cases

- 编辑"自动同步书籍"（`book/claude-code-book/`，由 GitHub Actions 每小时从
  书源仓库镜像）时怎么办？→ 系统允许编辑并在该书的编辑界面明确警示：
  同步任务会定期覆盖此目录的手动修改；或所有者自行确认放弃（见假设 A3）。
- 保存的文件不存在于远端（新章节）→ 按"新建文件"路径创建并提交。
- 凭据过期/权限不足 → 保存失败并引导重新确认身份，编辑内容不丢失。
- 保存的 Markdown 极大（如全文翻译论文 60KB+）→ 正常完成，不截断、不损坏。
- 编辑内容破坏了站点契约（如 SUMMARY 链接指向不存在文件）→ 允许保存
  （内容零丢失优先），但预览/保存提示中说明可能的渲染异常。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 仅在访客被验证为站点仓库所有者后，才在界面上展示
  任何编辑相关入口；对其他所有人（含未登录访客）MUST 完全隐藏编辑能力。
- **FR-002**: 所有者身份确认 MUST 在浏览器内完成，确认凭据 MUST 仅保存在
  该浏览器本地（localStorage），MUST NOT 出现在 URL、页面内容或任何公开
  接口的响应中。
- **FR-003**: 身份确认流程 MUST 校验该凭据对应的账号确实是站点仓库所有者；
  校验不通过时等同访客对待（无编辑入口、无法保存）。
- **FR-004**: 所有者 MUST 能够在阅读器中进入当前章节的编辑态，以纯文本
  编辑 Markdown 原文。
- **FR-005**: 编辑态 MUST 提供实时预览，预览渲染结果与阅读态渲染一致
  （同一渲染管线）。
- **FR-006**: 保存 MUST 以提交（commit）方式写回站点仓库对应文件；保存
  前系统 MUST 基于远端最新内容做冲突校验，冲突时 MUST NOT 静默覆盖，
  并保留本地编辑内容。
- **FR-007**: 保存结果 MUST 有明确反馈（成功/失败/冲突），失败时 MUST 保留
  编辑区内容并提供重试路径。
- **FR-008**: 所有者 MUST 能够编辑书籍目录（SUMMARY）以新增/删除/调整章节
  链接；新增指向不存在文件的链接在保存时按新建文件处理。
- **FR-009**: 存在未保存修改时，切换章节/书籍/关闭页面 MUST 触发放弃确认。
- **FR-010**: 编辑入口在未确认身份的所有浏览器会话中 MUST 默认不可见；
  已确认所有者的会话刷新页面后 MUST 无需重新确认（凭据有效期内）。
- **FR-011**: 系统 MUST 对自动同步书籍（`book/claude-code-book/`）的编辑界面
  展示同步覆盖警示。
- **FR-012**: 编辑相关日志（保存尝试、失败原因）MUST 仅保留在本浏览器本地，
  MUST NOT 上传到第三方服务。

### Key Entities *(include if feature involves data)*

- **Book（书）**: 已有概念——`book/<id>/` 下的章节集合；编辑功能作用于其
  章节 md 与 SUMMARY。
- **Chapter（章节）**: 单个 Markdown 文件；编辑的基本单位，含路径、原文内容。
- **Draft（草稿/未保存修改）**: 所有者在浏览器中产生的未落盘修改；生命周期
  限于当前浏览器会话，切换前有放弃确认。
- **OwnerSession（所有者会话）**: 身份确认后的本地凭据 + 所有者身份信息；
  支撑 FR-001/002/003/010。
- **ChangeRecord（保存记录）**: 一次成功保存对应的仓库提交（文件、时间），
  供成功反馈与失败排查引用。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对 100% 的非所有者访问（未登录/非所有者账号），页面不出现任何
  编辑入口，且其发起的保存尝试 100% 失败、`book/` 内容零变化。
- **SC-002**: 所有者在已授权浏览器中从打开页面到进入章节编辑态不超过
  10 秒；首次身份确认全流程不超过 1 分钟。
- **SC-003**: 所有者保存成功到线上内容可见（站点自动部署完成）不超过
  5 分钟。
- **SC-004**: 保存操作成功率 ≥ 99%（排除用户主动取消与网络断开）；冲突与
  失败场景中编辑内容零丢失率 100%。
- **SC-005**: 所有者可在不使用命令行的前提下完成"新增论文 → 加入目录 →
  上线"全流程（对照 `agent-papers` 日常维护场景）。

## Assumptions

- **A1（保存通道）**: 站点保持纯静态（Constitution 原则 II，不引入服务端），
  保存通过所有者在浏览器本地提供的 GitHub 访问凭据（细粒度 PAT，仅授予
  本仓库 Contents 读写）直接调用平台内容接口完成；不搭建任何后端服务。
- **A2（身份识别）**: "GitHub 所有者"通过凭据对应的账号与本仓库所有者账号
  匹配来判断；仓库所有者账号在本特性中固定为站点配置中的 owner（当前为
  LukeChou166）。组织账号/协作者不在 v1 范围。
- **A3（自动同步书籍）**: v1 允许编辑 `claude-code-book` 但显示覆盖警示
  （FR-011），不做"编辑自动回流书源仓库"的复杂方案（备选方案被否决理由：
  跨仓库提交与同步回写复杂度高，违背静态优先与简单性原则）。
- **A4（编辑器形态）**: v1 为纯文本 Markdown 编辑 + 实时预览，不做富文本/
  WYSIWYG。
- **A5（范围）**: 编辑仅覆盖 `book/` 下的内容文件与 SUMMARY；博客文章
  （`site-src/src/content/posts/`）在线编辑不在本特性范围。
- **依赖**: 站点托管平台的自动部署能力（push 后自动上线）为既有事实，本
  特性依赖但不改造它。
